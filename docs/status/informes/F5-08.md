Qué se hizo:
Implementación de autenticación LDAP sobre TLS (`control-plane/cercano-api/src/identity/ldap.rs`) y registro del endpoint `/api/auth/ldap/:provider/login`. Validación estricta de configuración TLS obligatoria (`ldaps://` o `start_tls: true`; rechazo de `ldap://` en plano), límite de timeout (<= 5000 ms), sanitización de consultas con escape RFC 4515 para evitar inyección en filtros, y mapeo de grupos basado exclusivamente en listas permitidas (`group_allowlist`). Ante usuarios inexistentes o credenciales erróneas se devuelve un error genérico indistinguible sin enumeración de cuentas. Cuando el directorio no está disponible o expira el timeout, se responde 503 sin sesión ni privilegios. Tras un bind exitoso y asignación de rol, se exige obligatoriamente el segundo factor TOTP de Cercano (202 Accepted con `mfa_token`) antes de emitir la sesión.
