# Informe de Tarea F4-04 — 2FA TOTP (Enrolamiento, Login en dos pasos, Recovery, Revocación)

```
ID: F4-04      Agente: ControlPlane      Estado: Hecho
Qué se hizo:
- Implementación completa del motor 2FA TOTP conforme a RFC 6238 en `control-plane/cercano-api/src/auth.rs`:
  * Enrolamiento con generación de secreto Base32 y URL `otpauth://` compatible con Google Authenticator / Microsoft Authenticator.
  * Confirmación de enrolamiento con código TOTP válido y generación de 8 códigos de recuperación de un solo uso protegidos mediante hash SHA-256 (`recovery_codes`).
  * Desafío MFA de dos pasos en el endpoint de login (`POST /api/auth/login`): retorno de estado HTTP 202 Accepted con token de desafío efímero `mfa_token` (TTL 5 minutos).
  * Verificación de segundo factor (`POST /api/auth/2fa/verify`) aceptando código TOTP de 6 dígitos o código de recuperación alfanumérico insensible a formato.
  * Consumo atómico de códigos de recuperación marcándolos como usados para prevenir reuso.
  * Protección contra fuerza bruta: bloqueo automático por 15 minutos (`account_locked`, HTTP 429) tras 5 intentos fallidos consecutivos de segundo factor.
  * Revocación completa de 2FA (`POST /api/auth/2fa/revoke`) por el propio usuario o por un administrador, con invalidación inmediata de todas las sesiones activas del usuario.
- Cobertura de pruebas completa en `tests/two_factor_auth_test.rs` y `tests/m2_challenger_stress_test.rs`.

Evidencia:
- Pruebas unitarias e integración en WSL Arch Linux:
  * `tests/two_factor_auth_test.rs`: 5/5 pasadas.
  * `tests/m2_challenger_stress_test.rs`: 4/4 pasadas (expiración de desafío a 5 min, formato de códigos de recuperación, revocación multi-sesión, bloqueo por 5 intentos y auto-desbloqueo).
- `cargo clippy -p cercano-api --all-targets -- -D warnings`: 0 advertencias.
- `tools/check-license-headers.sh`: 100% conforme (AGPL-3.0).
- Zero Secrets: Secreto TOTP nunca se expone en logs ni en respuestas tras la confirmación; códigos de recuperación almacenados únicamente como hashes SHA-256.
```
