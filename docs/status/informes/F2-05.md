# Informe F2-05 — Hooks de auditoría del cliente

ID: F2-05      Agente: Cliente      Estado: En verificación

Qué se hizo:
- Se regeneró `patches/004-client-audit-hooks.patch` contra `vendor/client` para propagar `conn_audit_ref` como `trace_id` en las transferencias de archivos.
- Se implementaron los puntos de endurecimiento y consistencia en `control-plane/cercano-api/src/routes/audit.rs`:
  1. **Autenticación estricta (Fix 1):** Se cerró el bypass de autenticación por mero nombre de dispositivo. `/api/audit/conn` y `/api/audit/file` exigen `X-Cercano-Internal-Token` o Bearer admin. La ingesta directa sin token queda en 401; el flujo operativo previsto es que el servidor/relay reenvíe los eventos con el token interno. La ingesta directa autenticada desde cliente terminal requerirá una tarea futura con secreto por dispositivo (`token_hash`, `X-Cercano-Device-Token`).
  2. **Estandarización de Actor y Sujeto (Opción A):** Actor = quien inicia la acción/control (`peer` o `peer_id` para `conn.auth` y `file.transfer`; IP del cliente iniciador en `conn.start`). Sujeto = terminal o dispositivo accedido/controlado (`id`, equipo que reporta). La IP del actor se extrae del payload (`payload.ip` o `info.ip`) en lugar de atribuir erróneamente la IP del socket del host controlado al controlador.
  3. **Throttle por dispositivo (Fix 3):** Se añadió `allow_ingest` con ventana de 1 segundo y límite de 1000 eventos/s por dispositivo, devolviendo 429 Too Many Requests (`rate_limited`).
  4. **IP del actor preservada e IP del socket como fallback (Fix 4):** Se asigna la IP del cliente iniciador reportada en el payload, usando la IP derivada del socket de conexión mediante `extract_client_ip` únicamente como fallback en caso de ausencia.
  5. **Trace único y helper compartido (Fix 5 + 8):** Se introdujo `legacy_trace_id(device, conn_id, explicit)` con formato `conn-{device}-{conn_id}-{YYYYMMDD}`.
  6. **Normalización y prueba de `conn_type`:** Se normalizan enteros `0..=4` (`0=remote`, `1=file_transfer`, `2=port_forward`, `3=view_camera`, `4=terminal`) a cadenas legibles, probado tanto a nivel unitario (`normalize_conn_type_maps_integers_and_strings`) como en la suite de integración de rutas.
  7. **Especificación actualizada (Fix 6):** Se documentaron en `docs/specs/audit-events.md` las acciones `conn.auth` (6.3, con Sujeto = equipo accedido y Actor = par iniciador), `conn.event` (6.4) y la numeración consecutiva 6.1 a 6.14.
  8. **Carrera de nonce (Fix 7):** Se capturan violaciones de unicidad en la base de datos de auditoría para tolerar reintentos concurrentes sin error.
