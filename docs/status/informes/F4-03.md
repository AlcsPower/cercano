# Informe F4-03 — API de usuarios, roles y ajustes

**ID:** F4-03 · **Agente:** ControlPlane · **Estado:** En verificación · **Fecha:** 2026-11-10

## Qué se hizo

- Se creó `src/permissions.rs` con el mapa fijo rol → permisos (`admin`, `operator`, `auditor`, legacy `user`) y pruebas unitarias.
- Se creó `src/routes/admin.rs` con:
  - `GET/POST /api/users`, `GET/PATCH/DELETE /api/users/:id`.
  - `GET /api/roles` (matriz fija de roles/permisos, solo admin).
  - `GET/PATCH /api/settings` (claves `console.organization_name` y `console.support_email` en `system_info`, sin migración nueva).
- El listado de usuarios oculta `password_hash`, `totp_secret` y `recovery_codes`; devuelve `totp_enabled`/`is_2fa_required` como booleanos.
- Se protegen las operaciones con `users:read/manage`, `roles:read`, `settings:read/manage`; un usuario no admin solo ve/edita su propia cuenta y no puede cambiar rol/estado. Se impide degradar/desactivar/eliminar al último administrador y editarse a sí mismo.
- Se añadieron pruebas de integración de RBAC, ajustes y último administrador (`tests/users_admin_test.rs`).
- Se actualizaron `lib.rs` y `routes/mod.rs` con las rutas.

## Desviaciones

- Los ajustes usan la tabla existente `system_info` con prefijo `console.`; evita una migración adicional y no duplica la marca del chat (F4.5-16).
- F4-03 no incluye los endpoints de 2FA (F4-04) ni el middleware general/`chat:*` (F4-05). Las comprobaciones de permiso van en cada handler de este módulo.
- Las acciones de auditoría nuevas `console.user_update`, `console.user_delete` y `console.settings_update` usan el patrón `console.*` ya admitido por el esquema; falta documentarlas en `audit-events.md` (F4-08/seguridad).

## Riesgos / deuda

- **Sin compilación ni pruebas ejecutadas**: errores de tipos o de SQL pueden aparecer en CI. El primer paso de QA es `cargo test -p cercano-api`.
- El borrado de usuario puede fallar por FK de `build_jobs`; se devuelve 409 y se recomienda desactivar en lugar de eliminar. Falta una prueba específica de esa ruta.
- La lista de permisos es fija en código; F4-05 debe usarla en el middleware y en `chat:*` sin duplicar reglas.
- `system_info` es compartida con otra información del servidor; las claves `console.*` evitan colisiones conocidas.
