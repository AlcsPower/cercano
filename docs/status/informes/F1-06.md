Qué se hizo:
- Se implementó en `control-plane/cercano-api` el módulo `src/server_keys.rs` para lectura, validación y rotación criptográfica segura de claves Ed25519 del servidor rendezvous/relay (`hbbs`/`hbbr`).
- Se expuso el endpoint público sin autenticación `GET /api/server/public-key` que retorna la clave pública activa del servidor (`{"public_key": "...", "key_type": "ed25519"}`) para aprovisionamiento dinámico de clientes y consola web.
- Se implementó el endpoint protegido `POST /api/server/keys/rotate` con autorización estricta para el rol `admin`, generación criptográfica con CSPRNG (`OsRng`), respaldo automático timestamped de claves previas y actualización atómica en disco con permisos POSIX `0600` en la clave privada.
- Se garantizó la regla crítica de seguridad: la clave privada NUNCA se expone en la API, logs ni respuestas HTTP.
- Se elaboró la guía de procedimiento `docs/guias/rotacion-claves.md` cubriendo rotación, respaldos cifrados fuera de línea (GPG/Age) y mitigación de rechazo de clientes antiguos (TC-F1-031).
