# Informe de tarea: F1-05 — Registro de dispositivos en cercano-api

```
ID: F1-05        Agente: ControlPlane      Estado: En verificación
Qué se hizo:
- Se implementó el módulo `src/devices.rs` en `control-plane/cercano-api` para la gestión y registro del ciclo de vida de dispositivos clientes.
- Se incorporó la migración `003_device_metadata` en `src/db.rs` añadiendo columnas `version` e `ip_address` con índice sobre `last_seen_at`.
- Se implementaron los endpoints:
  * `POST /api/devices/heartbeat`: registra o actualiza mediante UPSERT el dispositivo (`id`, `name`/`hostname`, `os`, `version`, IP detectada o provista), actualiza `last_seen_at` con timestamp UTC actual y fija estado `online`.
  * `GET /api/devices`: lista todos los dispositivos con estado dinámico (`online` o `offline`) calculado en base al tiempo de gracia configurable (`device_grace_period_secs`, por defecto 60 segundos desde `last_seen_at`), protegido por autenticación Bearer (`AuthenticatedUser`).
  * `GET /api/devices/:id`: detalle de un dispositivo específico con su estado calculado según el tiempo de gracia.
  * `DELETE /api/devices/:id`: eliminación de dispositivos protegida exclusivamente para usuarios administradores (`role == "admin"`).
- Se agregaron parámetros de configuración en `src/config.rs` (`device_grace_period_secs`, variable de entorno `CERCANO_DEVICE_GRACE_PERIOD_SECS`).
- Se actualizó la especificación OpenAPI en `docs/specs/api.yaml` reflejando rutas y esquemas `HeartbeatRequest`, `DeviceResponse` y `DeleteDeviceResponse`.
- Se implementaron las pruebas unitarias e integración en `tests`:
  * `TC-F1-020`: Cliente nuevo aparece en la API con su ID y estado en línea.
  * `TC-F1-021`: Cliente sin heartbeat pasa a fuera de línea tras el tiempo de gracia.
  * Pruebas de control de acceso y eliminación (admin vs usuario estándar 403, 404 para inexistente, 401 para accesos no autenticados).
```
